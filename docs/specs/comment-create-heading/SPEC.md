# SPEC: 新規コメントの案内見出しを削除する

## 1. 目的

新規コメントは空の本文欄から書き始められる。本文の先頭に書いた Markdown 見出しは、保存・同期時にも保持する。

## 2. 対象外

- 既存コメントの編集テンプレート、下書きの一括移行、同期処理や Dashboard の操作手順の変更。

## 3. 受け入れ条件

- [ ] 新規コメントを開くと、Markdown に `mode: comment-create` と対象チケットの `issue_id` を含む YAML フロントマターが入り、その下の本文欄は空である。
- [ ] 本文の最初の空白でない行に `# 調査結果` または `#` を書いて保存・同期すると、その行を含む本文が対象チケットに投稿される。
- [ ] 最初の空白でない行が、対象チケットの旧自動生成見出しと完全一致する場合は、その見出しだけを互換処理で除外する。後続の本文見出しと別のチケット番号を含む見出しは保持する。
- [ ] 旧自動生成見出しと同じ行を新規下書きの本文先頭に手入力した場合も、互換処理で除外される。
- [ ] 空のテンプレートからは空の本文が得られる。不正な `issue_id` や別の `mode` は新規コメント形式として受け付けない。

## 4. 公開 API・DB スキーマ

変更なし。

## 5. 制約

- 投稿先の判定、接続スコープの分離、既存の保存・同期経路を維持する。
- [コメント機能仕様](../../features/comments.md) を実装と同じ変更で更新する。

## 6. 必須テスト

- **単体**　初期テンプレート、先頭見出しの保持、旧見出しの除外、空の本文、不正なメタデータを検証する。先頭見出しの保持を検証するテストが旧実装で失敗することも確認する。
- **統合**　Extension Host で、新規コメントの保存・同期経路を通して、先頭見出しを含む本文が対象チケットへの送信内容に含まれることを確認する。
- **回帰**　既存コメントの編集形式とプレーンテキストからの本文抽出を確認し、型チェック、lint、テストのコンパイルを実行する。
