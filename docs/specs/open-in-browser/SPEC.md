# SPEC: チケットとコメントの「ブラウザで開く」を共通化する

## 1. 目的

チケットとコメントのパレットコマンドを **「Redmine: ブラウザで開く」** に統合する。呼び出し元に応じて対象を判定し、既存コメントは Redmine 上の該当箇所を開く。

## 2. 対象外

- プロジェクトをブラウザで開くコマンド。
- Dashboard の選択やエディター追従の仕様。チケットとコメントの編集、保存、同期。

## 3. 受け入れ条件

- [ ] コマンドパレットにはチケット・コメント共通の **「Redmine: ブラウザで開く」** が1件表示される。日本語と英語の表示名を用意する。
- [ ] Dashboard のボタンは押した行を、エディター上部のボタンは渡された文書 URI を対象にする。他のチケットやコメントが選択中でも、明示された対象を優先する。
- [ ] パレット実行時はアクティブな Redmine エディターを優先する。該当エディターがなければ、Dashboard の選択中チケットに属する選択済みコメント、次いで選択中のチケットを開く。チケットだけが選択されている場合は直接開く。
- [ ] 既存チケットと新規コメント下書きは `/issues/<ticketId>` を開く。既存コメントは `/issues/<ticketId>#note-<noteIndex>` を開く。コメント位置は同じチケットの Dashboard データから取得し、見つからなければ既存の Redmine コメント取得処理で照会する。
- [ ] コメント位置を特定できない場合は通知して中止する。対象なし、未同期の新規チケット、接続先不一致、URL 生成失敗、ブラウザ起動失敗もそれぞれ通知する。対象の解決に失敗した場合はそこで終了する。
- [ ] 旧コマンド ID で既存のキーバインドと `executeCommand` 呼び出しを維持する。旧チケットコマンドは URI、Dashboard の選択、アクティブエディターの順で対象を解決する。旧コメントコマンドは Quick Pick を維持し、選択後は共通のコメント位置解決を使う。キャンセル時はそのまま終了する。

## 4. 公開 API・DB スキーマ

- `redmine-client.openInBrowser` の引数は省略可能な文書 URI。省略時はパレットと同じ選択規則を使う。
- `redmine-client.openTicketInBrowser` と `redmine-client.openCommentInBrowser` は互換用として登録し、パレットから非表示にする。
- Dashboard の Webview メッセージ形式、Redmine API、永続化スキーマは対象外。

## 5. 制約

- 文書は `connectionScope` が現在の接続先と一致するときに限り対象にする。コメントの照会とブラウザ起動を同じ接続先に限定し、照会中に接続先が切り替わった場合は起動前に中止する。ブラウザ URL から認証情報を除く。
- Dashboard の要求は既存の Webview メッセージ検証を通す。ユーザー向け通知は `vscode.l10n.t` を使う。
- チケット・コメントの正本仕様、README の操作案内、`verification/feature-map.json` を実装と同じ変更で更新する。

## 6. 必須テスト

- **単体**　明示された URI、アクティブエディター、Dashboard の選択が異なる場合に対象の優先順位を検証する。コメント ID と注記番号が異なるデータで URL を検証し、旧処理を再現した場合に検証が失敗することを確認する。
- **統合**　登録済みの共通コマンドを引数なしと URI 付きで実行し、ブラウザに渡す URL を確認する。コメント位置の照会成功と失敗、照会中の接続切替、対象なし、未同期の新規チケット、起動失敗も検証する。
- **回帰**　旧 ID と Quick Pick、Dashboard の既存ボタン、プロジェクトコマンドを確認する。共通コマンドだけがパレットに表示されることをマニフェストで検証し、型チェック、lint、関連する Extension Host テスト、検証ゲートを実行する。
