# SPEC: Dashboard からのチケット・コメント削除

## 1. 目的

Dashboard のチケット行とコメント行のオーバーレイに「削除」ボタンを追加する。ユーザーが対象を確認して承認したとき、そのチケットまたはコメントを現在の Redmine 接続先から削除する。

## 2. 対象外

- 一括削除、削除の取り消し、オフライン削除の予約、Dashboard の行オーバーレイ以外への削除操作の追加。
- ローカルの Markdown ファイルの削除、障害復旧用の補償処理の変更。

## 3. 受け入れ条件

- [ ] **AC1 ボタン**　既存のチケット行とリモートコメント行をホバーまたはキーボードでフォーカスすると、既存アクションと並んで、マウスとキーボードで操作できる「削除」ボタンが表示される。未作成の `#NEW` チケットと未投稿コメントの行には表示しない。
- [ ] **AC2 確認**　ボタンを押すと、その行のチケット番号と件名、またはコメントの親チケット番号とコメントを識別できる情報をモーダルに表示する。チケットの確認には、配下のチケット、コメント、作業時間の記録などが Redmine の仕様に従って削除されることを示す。「削除」を明示的に選んだ場合だけ書き込む。キャンセル、`Escape`、ダイアログを閉じる操作では、削除の書き込みもローカル状態の変更も行わない。
- [ ] **AC3 対象と接続先の照合**　確認の前と承認後の送信直前に、Extension Host が対象のリモート ID、コメントと親チケットの対応、`connectionScope` を照合する。不正な ID、親子の不一致、対象を特定できない要求、確認中に接続先が切り替わった要求では削除を書き込まない。別の行が選択されても確認に表示した対象を使い、接続切り替え後に到着した結果は新しい接続先の画面や状態に反映しない。
- [ ] **AC4 保留項目の確認と保護**　チケット削除前に、対象または配下にある保留項目と、親子関係を HTTP 403 または 404 により照会できなかった保留項目を表示する。項目ごとに変更の種類、変更先のチケット・コメント番号または下書き名、読めなかった参照先を区別する。Unsynced に未保存の編集も表示する。確認画面から変更の読み取り専用表示や該当する Unsynced 項目を開いた場合は、その削除確認を終了する。チケット行の「削除」を再度押すと、新しい確認を表示する。「開く」で削除、保存、同期を行わない。対象または配下にある未同期変更が判明している場合や、確認できる手段がない項目がある場合は、その理由を示して承認操作を出さない。親子関係のみ不明で全項目を確認できる場合は、Redmine 上の反映先が配下なら削除されることを示し、明示承認後だけ削除する。送信直前に接続先、項目と内容、影響範囲を再照合し、変化があれば送信しない。送信後から結果確定までは対象範囲の同期書き込みと重複させない。子チケットがない場合は対象チケットの変更だけを照合する。コメント単体の削除では、対象コメントに未同期の変更があれば中止する。下書き、ファイル、キューは保持する。
- [ ] **AC5 チケット削除**　承認後に対象チケット 1 件を指定して Redmine に削除を要求する。書き込みが受理され、同じ接続先の詳細照会で対象の消失を確認したら、Dashboard の一覧と検索結果を更新する。削除されたチケットが選択中なら選択を解除して詳細ドロワーを閉じる。
- [ ] **AC6 コメント削除**　承認後に対象 journal の本文を空にする。書き込みが受理され、同じ接続先の親チケットを再取得して対象コメントの本文が消えたことを確認したら、コメント行と件数を更新する。削除したコメントが選択中ならコメントの選択を解除する。親チケットと他のコメントは引き続き表示でき、journal に記録されたフィールド変更履歴は Redmine に残る。
- [ ] **AC7 失敗と重複 [ASSUMPTION]**　削除はその場で Redmine に送信する。権限拒否や送信前の通信不能では理由を通知し、削除を書き込んだ後のタイムアウトや再取得失敗で結果を確定できない場合は、削除結果を確認できなかったことを通知する。削除を確定する前に行を消さず、結果不明時は読み取りで再確認し、削除リクエストを自動で再送しない。同じ対象への連打では、確認と処理の完了まで削除リクエストを重複送信しない。
- [ ] **AC8 既存操作**　チケットとコメントの同期、ブラウザーで開く操作、行選択、未同期下書きの既存操作が従来どおり動く。
- [ ] **AC9 読み取り専用の下書きの破棄**　Unsynced で内容を確認できる読み取り専用のローカル下書きについて、対象番号付きの確認を経て「下書きを破棄」できる。破棄の条件と保持するデータは [保存と同期](../../features/offline-sync.md) に従う。破棄後にチケット行の「削除」を押すと、最新の保留項目で再判定する。

## 4. 公開 API・DB スキーマ

- チケットは `DELETE /issues/{issueId}.json` を使う。関連データへの波及は Redmine 標準の削除動作に従う。[Redmine REST Issues](https://www.redmine.org/projects/redmine/wiki/rest_issues#Deleting-an-issue) · [Redmine 6.1 のチケット削除処理](https://github.com/redmine/redmine/blob/6.1-stable/app/controllers/issues_controller.rb#L403-L449)
- Redmine 6.1 の `include=children` では、子チケットがない場合は `children` を省略する。子チケットが存在し、権限により全件が非表示の場合は空配列を返す。[Redmine 6.1 の子チケット応答](https://github.com/redmine/redmine/blob/6.1-stable/app/helpers/issues_helper.rb#L626-L638)
- コメントは `PUT /journals/{journalId}.json` に `{"journal":{"notes":""}}` を送る。`journalId` には永続 ID を使う。変更履歴を持つ journal は本文が空の状態で残り、変更履歴のない journal は削除される。[Redmine REST Journals](https://www.redmine.org/projects/redmine/wiki/Rest_Journals#Deleting-a-journal)
- 外部向けのコマンドや API の追加は対象外。削除をキューに登録するための永続化スキーマ変更も対象外。

## 5. 制約

- Webview の要求は `dashboardProtocol.ts` と `dashboardMessageValidation.ts` を通し、正の安全な整数 ID と現在の接続先に紐付く対象を照合する。削除の権限判定は Redmine の応答に従い、書き込みと読み戻しには同じ `connectionScope` の認証情報を使う。
- 変更を開く操作は Extension Host が対象と接続先を照合し、確認用の読み取り専用文書を開く。Webview から任意のファイルパスを受け取らない。
- 既存の同期ライフサイクルに従い、`src/app/syncEngine.ts` と `src/app/ticketSync/` が定めるリモート書き込み、読み戻し・照合、ローカル確定の順序を守る。結果が不明な書き込みは再送前に照合する。
- ユーザー向け文字列は `vscode.l10n.t` を使う。実装と同じ変更で Dashboard・チケット・コメントの正本仕様、README の操作案内、`verification/feature-map.json`、関連テストを更新する。

## 6. 必須テスト

- **単体**　不正 ID、別チケットの journal、確認中の接続切り替え、確認中に発生した未保存変更、配下の未同期変更、同一対象への連打を検証する。コメント削除に注記番号を使った場合や、キャンセル後にリクエストを送った場合にテストが失敗することを確認する。
- **統合・UI**　マウスとキーボードでのボタン操作、取消時の書き込みゼロ、別行を選択中に押した行の削除を検証する。実際に送るメソッド・パス・本文、削除後の一覧・選択・コメント件数、履歴を持つ journal の扱いを確認する。権限拒否、タイムアウト、読み戻し失敗、処理中の接続切り替えでは誤った画面更新や自動再送が発生しないことを確認する。
- **保留項目の確認**　別チケットを親として参照する未保存下書きが Unsynced に表示されることを確認する。読み取り専用表示を閉じて同じチケットの削除を再度実行できることと、確認から Unsynced の該当項目へ移動できることを確認する。開く・取消・未確認項目・内容変更・接続切り替えでは削除要求を送信しない。番号だけを表示して承認できる旧挙動を入れるとテストが失敗することを確認する。
- **回帰**　チケット・コメントの既存アクションと、未作成チケット・未投稿コメントのオーバーレイを確認する。型チェック、lint、関連する Dashboard UI と Extension Host のテスト、`verify:all` を実行する。
- **下書きの破棄**　3 種類の下書き、同一内容の複数の下書き、取消、確認中の内容変更・接続切り替え、関連編集・同期による中止を検証する。破棄で件数が減り、Redmine に書き込まず、既存キューと別の下書きを保持することを確認する。破棄した項目だけがチケット削除を止めていた場合は、そのチケットを削除できることを確認する。
