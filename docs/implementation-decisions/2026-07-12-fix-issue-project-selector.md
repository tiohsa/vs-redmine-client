## 依頼と参照元の要約

プロジェクト変更を単一の非同期処理に統一し、重複したチケット取得と古い API レスポンスによる状態上書きを防ぐ。実行時の選択状態を永続化設定から分離し、プロジェクト変更時に旧プロジェクトの依存状態をクリアし、Dashboard とコマンドパレット双方および競合・エラー系をテストする。

## 記録方針

このファイルには、参照元に明記されていなかった実装中の判断、変更、妥協点、仕様解釈、未解決事項、検証上の制約を記録する。

## 判断一覧

### D-001 CodeGraph 未初期化時の調査方法

- 種別: 技術制約
- タイミング: 実装前
- 参照元に書かれていたこと: 最新コードを調査して修正すること。
- 参照元に書かれていなかったこと: CodeGraph が利用できない場合の代替手順。
- 判断: CodeGraph の初期化を待たず、既存の `rg`/ファイル読込で構造を調査する。
- 理由: 現在のプロジェクトに `.codegraph/` がなく、修正作業を外部状態の変更待ちで停止させないため。
- 代替案: `codegraph init -i` を実行してから調査する。
- 影響: 構造検索の効率は下がるが、実装・検証は継続できる。
- 可逆性: 高。後からインデックスを作成して再確認できる。
- 制約: 制約により必須
- ユーザー確認: 事後報告

### D-002 実行時プロジェクト状態と選択操作の直列化

- 種別: 解釈
- タイミング: 実装中
- 参照元に書かれていたこと: 実行時状態を永続化設定から分離し、選択処理を完了待ち可能にすること。
- 参照元に書かれていなかったこと: 短時間に複数のプロジェクト選択が発生した場合の順序。
- 判断: `DashboardProjectService` が選択状態をメモリに保持し、選択操作自体を FIFO で直列化する。
- 理由: 各選択処理が対象プロジェクトを確定してから保存・チケット取得するため、選択途中で別の実行時状態を参照しない。
- 代替案: 全選択を並列に実行し、チケット側の世代判定だけで抑止する。
- 影響: 選択操作が順番に反映され、最後の選択が最終状態になる。API の不要な同時実行を減らす。
- 可逆性: 高。キューを外しても世代判定は独立して利用できる。
- 制約: 任意判断
- ユーザー確認: 事後報告

### D-003 コマンドパレットの ID 入力維持と一覧検証

- 種別: 解釈
- タイミング: 実装中
- 参照元に書かれていたこと: QuickPick を推奨し、代替として取得済み一覧に存在する ID の検証を認める。
- 参照元に書かれていなかったこと: 既存コマンドの入力 UI を必ず変更するかどうか。
- 判断: 既存の InputBox UI を維持し、取得済み Dashboard プロジェクト一覧に存在する ID のみ受け付ける。
- 理由: ユーザー向け UI 変更を広げず、仕様が認める代替方式で不正 ID の保存を防げるため。
- 代替案: QuickPick に全面変更する。
- 影響: 既存の ID 入力体験を維持しつつ、未知の ID は選択状態を変更しない。
- 可逆性: 高
- 制約: 任意判断
- ユーザー確認: 事後報告

追記: コマンド実行時に Dashboard がまだ表示されておらず一覧未取得でも機能するよう、選択処理側が一覧を一度ロードしてから ID を検証する構成にした。そのためコマンド側は一覧を直接参照せず、選択処理の明確なエラーを表示する。

### D-004 コメント取得もプロジェクト変更で無効化

- 種別: 仕様ギャップ
- タイミング: 実装中
- 参照元に書かれていたこと: プロジェクト変更時にコメント一覧とコメント対象チケット ID をクリアすること。
- 参照元に書かれていなかったこと: 変更前に開始したコメント API の応答を破棄する具体策。
- 判断: コメントサービスにも世代判定を追加し、プロジェクト変更時に世代を無効化する。
- 理由: チケット一覧だけを保護すると、旧チケットの遅延コメント応答がリセット済み状態を再汚染するため。
- 代替案: プロジェクト変更時にコメント状態だけをクリアし、応答順は許容する。
- 影響: 旧チケットのコメント成功・失敗が新プロジェクトの表示へ反映されない。
- 可逆性: 高
- 制約: 任意判断
- ユーザー確認: 事後報告

## 変更・逸脱

仕様の推奨 UI である QuickPick への変更は行わず、既存 InputBox と選択処理側の一覧検証を採用した。既存 UI の変更範囲を抑えつつ、未知の ID を保存しない要件を満たすためである。

## 妥協点と残課題

通常権限では VS Code Electron sandbox が `Operation not permitted` となった。ユーザー承認の sandbox 外再試行では `pnpm run test:unsafe` が成功したため、統合テストの未実行は解消した。

## 検証と制約

- 実行した検証: `pnpm exec tsc --noEmit`、`pnpm run lint`、`pnpm run package`、承認済みの `pnpm run test:unsafe` に成功。テストは 720 passing。競合テストを追加し、通常 `pnpm test` でも compile-tests/compile/lint フェーズ成功を確認。
- 実行できなかった検証: 通常権限での Electron sandbox 有効テストはホスト権限制約で `SIGTRAP` 終了。CodeGraph は未初期化のため利用していない。

## 結果

プロジェクト選択の非同期処理を完了待ち可能にし、実行時選択状態をメモリに保持、選択操作を直列化した。チケットとコメントの古い応答を世代判定で破棄し、旧プロジェクトの表示状態を変更時にクリアする実装を完了。統合テストを含む検証も完了した。
