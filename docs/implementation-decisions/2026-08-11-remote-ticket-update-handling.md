## 依頼と参照元の要約

未保存のローカル編集を失わないよう、Redmine からの手動再読込を安全化する。自動ポーリングは今回の実装対象から外す。

## 記録方針

このファイルには、参照元に明記されていなかった実装中の判断、変更、妥協点、仕様解釈、未解決事項、検証上の制約を記録する。

## 判断一覧

### D-001 変更有無は同期済み基準値と現在の本文から判定する

- 種別: 解釈
- タイミング: 実装前
- 参照元に書かれていたこと: チケットは `TicketDraft`、コメントは `CommentEdit` の基準値と現在のエディター内容を比較して確認対象を決める。
- 参照元に書かれていなかったこと: 構文不正なチケット本文や基準状態が存在しない場合の扱い。
- 判断: チケット本文を解析できない場合、または対応する基準状態がない場合は保守的に「ローカル変更あり」と扱う。コメントは既存の保存ロジックに合わせて `trim()` 後の本文を比較する。
- 理由: 再読込は破壊的な置換であり、誤って確認を省略するより、不要な確認を一度出す方が安全なため。
- 代替案: `TextDocument.isDirty` のみを使う。untitled 文書や拡張機能が書き換えた文書で同期基準との差異を正確に表せないため採用しない。
- 影響: 壊れた Markdown や状態未初期化のエディターでは確認が表示される。
- 可逆性: 高。判定関数を変更すれば調整できる。
- 制約: 任意判断
- ユーザー確認: 事後報告

## 変更・逸脱

現時点ではなし。計画どおり、手動再読込のみを安全化した。

## 妥協点と残課題

自動ポーリングと、リモート差分を表示する競合ビューへの直接遷移は今回実装しない。

## 検証と制約

- 実行した検証: `pnpm run compile`、`pnpm run lint`、`pnpm test -- --grep "Reload safety"`。統合テストは834件すべて通過した。
- 実行できなかった検証: 初回の sandbox 内テストは VS Code Electron の `sandbox_host_linux.cc:41` で停止したため、同一コマンドをサンドボックス外で再実行した。実行中に `ENOSPC` のファイル監視警告が出たが、テスト結果への影響はなかった。

## 結果

`src/views/reloadSafety.ts` を追加し、チケット・コメントのローカル変更判定と再読込確認を共通化した。`reloadTicketFromEditor` と `reloadCommentFromEditor` は、変更を検出した場合に「Reload and Discard Changes」を明示選択したときだけサーバ内容を適用する。自動ポーリングは実装していない。
