# SPEC: 新規チケット同期時の 403

## 1. Goal
新規同期で拒否された操作を特定できるようにし、不要なステータス一覧取得による作成失敗を解消する。VS Code コマンドと Dashboard のどちらから一括同期しても、結果通知に失敗した操作名と HTTP ステータスを表示する。

静的調査では resolveMetadataForCreate が status 未指定でも一覧を取得し、取得失敗時は作成前に終了する。凍結済みリクエストの再試行にも結果を使わない一覧取得がある。共通 HTTP エラーには操作名がなく、報告された 403 の発生箇所は未確定。実環境での切り分けには、同時刻のアクセスログのメソッド、パス、応答コードを照合する。

## 2. Non-goals / Out-of-scope
- Redmine の権限変更、既存チケット編集への変更、自動再試行の追加。
- Dashboard のレイアウト変更や、単件同期の通知経路の見直し。

## 3. Acceptance Criteria
- [ ] status が空で他の必要な操作が許可されている場合、ステータス一覧を取得せず、status_id を省略して一度だけ作成し、読み戻しとローカル確定を完了する。
- [ ] status を指定して一覧取得が 403 の場合、一覧取得の拒否を表示し、作成 POST を送らない。
- [ ] 作成 POST が 403 の場合、作成操作と 403 を表示し、自動再送しない。
- [ ] 既存仕様で許可された明示的再試行は凍結済みリクエストを使い、ステータス一覧を再取得しない。
- [ ] 指定した有効なステータスは従来どおり対応する ID で送る。
- [ ] VS Code コマンドと Dashboard の一括同期で、ステータス一覧取得が HTTP 403 を返した場合は一覧取得と 403 を、作成 POST が HTTP 403 または 503 を返した場合は作成と該当コードを、それぞれ既存の結果通知に表示する。他の項目が同期に成功した場合も、失敗した新規チケットの診断を表示する。
- [ ] 作成 POST が 503 の場合は復旧待ちとして通知し、作成結果を `commit_unknown` として保持する。通常の同期を再実行しても POST は増えない。

## 4. Public API / DB Schema
変更なし。

## 5. Constraints
- 診断には操作名と HTTP ステータスを使い、API キー、リクエスト本文、応答本文を含めない。表示は `vscode.l10n.t` を使う。
- [ASSUMPTION] Dashboard からの一括同期では VS Code の結果通知を引き続き抑制し、既存の Dashboard の結果通知に診断を追加する。
- 接続スコープ、再試行の適格条件、書き込み・読み戻し・確定の順序を維持する。

## 6. Required Tests
- **Unit:** status の空値・有効名・未知名について一覧取得回数、解決結果またはエラーを確認する。
- **Integration / E2E:** 新規同期の一覧取得と作成 POST に個別に 403 を返し、一括同期の警告、POST 回数、未確定状態を検証する。作成 POST の 503 でも警告に操作名とコードを表示し、結果不明の保持と自動再送の抑止を確認する。各警告に応答本文が含まれないことを確認する。空の status では一覧取得だけが拒否される条件で同期完了を確認する。
- **Integration / E2E（Dashboard）** Dashboard の一括同期を入口に、一覧取得 403、作成 POST 403、作成 POST 503 をそれぞれ発生させ、結果通知の操作名とコード、応答本文の非表示、VS Code の結果通知が出ないことを確認する。作成 POST 503 では復旧待ちとして表示されることを確認する。別項目の同期成功と作成 POST 403 が混在する場合も、Dashboard の通知に作成と 403 が出ることを確認する。
- **Regression:** 明示的再試行で凍結済みペイロードが保持され、一覧取得がゼロであることを確認する。既存の新規作成・再試行テストを通す。
